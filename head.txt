frame < AUDIO_DMA_FRAMES; frame += OUTPUT_DMA_SIZE)\n310:         mixer_calcNextSampleBlock(&buf[frame * 2], &buf2[frame * 2]);\n311:     audioCodec_commitRenderBuffer();\n312: }\n313: ```\n314: \n315: **OUTPUT_DMA_SIZE = 32** is the effective LXR-master DSP/control block (confirmed correct in Session 019 — do NOT revert to 16).\n316: **AUDIO_DMA_FRAMES = 96** is the hardware DMA half; render budget per queued hardware slot is **2.18ms** = 471,288 cycles at 216MHz.\n317: \n318: **DSP render must remain in the main loop.** Moving it to the DMA ISR creates a hard 2.18ms ceiling — when DSP expands beyond the budget the system locks up with no graceful degradation. Main loop allows unlimited expansion with underruns as the graceful signal.\n319: \n320: **SPSC queue**: 2-slot queue. `ready_head` is owned by ISR, `ready_tail` by main loop, and `ready_count` tracks free/full state for queueing and diagnostics.\n321: \n322: **CPU-use widget**: `audioCodec_getQueueFreePercent()` uses DWT cycle-counter accounting of `ready_count < 2`. This is an audio queue-free pressure meter, not generic MCU utilization.\n323: \n324: **24-bit output path (Session 022)**: `audioOutBuffer`/`audioOutBuffer2` are `sample_mx_t` (int32_t, signed-24 value in container). `pack_half()` emits a true 24-bit payload in both halfwords of each I2S frame. Do NOT re-add `LSW = 0` zeroing. Do NOT add a `>> 8` shift in `sampleMix_toS24()` — int16 voice values enter the mixer already scaled as `int16 << 8` via `bufferTool_convertInt16ToSampleMix()`; adding `>>8` at pack time was the loudness regression fixed in session 022.\n325: \n326: **Zero startup underruns**: boot SD operations complete before `audioCodec_init()`.\n327: Runtime kit/all/performance sound-apply completion is chunked after audio starts (Session 027): `menu_tickSoundApply()` drives `preset_tickDrumsetApply()` so only one voice's velocity/LFO modulation routing is applied per foreground pass. Boot-time pre-audio apply remains synchronous.\n328: \n329: ### Internal DAC — Must Never Be Enabled\n330: \n331: The STM32F765 has an internal 12-bit DAC on PA4 (DAC1_OUT) and PA5 (DAC2_OUT). These pins are also ADC1_IN4 and ADC1_IN5, used as slider inputs for RV6 and RV5. **The internal DAC must never be enabled.** Accidental DAC peripheral clock enable or pin mode change silently corrupts slider ADC readings.\n332: \n333: `TIM6_DAC_IRQHandler` is the vector table name for IRQ54 because TIM6 and the internal DAC share an IRQ line by ST hardware design. **This does not mean the DAC is in use.** Audio is handled entirely by external CS4344 codecs via I2S2 and I2S3.\n334: \n335: ---\n336: \n337: ## SD Card Architecture (implemented Sessions 12, 17, and Phase 2 start in 030)\n338: \n339: **SD operations must never block the main loop or any ISR at priority ≤ 4.**\n340: \n341: **Implemented solution**: asyncfatfs (Betaflight/Cleanflight library), fronted by `filesystem.c/h`.
